ADR-026

ADR-026-Security-Hardening-Contract.md

Accepted

Security Hardening (Phase 9 Scope Contract)

DOC-01, DOC-03, DOC-08, DOC-09, DOC-10, CONTEXT, .cursorrules

ADR-001, ADR-007, ADR-008, ADR-014, ADR-018, ADR-019–025

Pemetaan Berdasarkan Kluster Domain

1. Security, Identity & PII Boundary

ADR-001: Login tunggal username + password via Shield Session Authenticator di /cp.

ADR-008: Enkripsi email_ciphertext (Sodium XSalsa20-Poly1305) & email_lookup_hash (HMAC-SHA256) dengan key terpisah di .env.

ADR-014: Sanitasi HTML server-side allowlist (RichTextSanitizer) sebagai batas keamanan mutlak sebelum persistensi.

ADR-026: Phase 9 V1 Security Hardening contract — verify existing foundations (Shield/AuthZ/CSRF/HTMX session/RichText/Media/Preview/cache/scheduler); harden missing PII cipher wiring (ADR-008), CI4 Throttler on auth/recovery surfaces (capacities UNDEFINED/operational), SecureHeaders baseline (full CSP deferred), DOC-03 §25 auth audit events; no new permissions/endpoints; preserve ADR-019–025 (Task 9.1A).

2. Content Lifecycle, Concurrency & Presentation Contract

ADR-002: Format ThemeManifest.php murni array PHP, single active theme, template wajib custom-page, dan preservasi payload legacy non-destruktif.

ADR-022: V1 Theme discovery (`app/Views/themes/{id}/`); no `themes` table; ENABLED via `Config\Theme::$enabledThemeIds`; ACTIVE via Settings `Theme.activeThemeId` with Config bootstrap fallback; ADR-002 activation remains post-commit cache invalidate (Task 6.1A).

ADR-023: V1 Theme Preview — Page-only, ENABLED Theme, Admin + `theme.preview`, GET `/admin/preview/theme/{themeId}/page/{pageId}`; cache bypass; no ACTIVE/Settings mutation; no Preview audit event (Task 6.2A).

ADR-004: Engine validasi skema 7 tipe skalar + Repeatable Blocks native PHP 8.5 tanpa dependensi library JSON Schema eksternal.

ADR-005: Snapshot revisi JSON lengkap, isolasi auto-save (is_autosave = 1), OCC lock_version (HTTP 409), dan proteksi konten PUBLISHED saat drafting.

ADR-019: V1 Revision + Audit foundation — `revisions` / `audit_logs` DDL; snapshot JSON `schema_version` 1 for Page/Post; `pages`/`posts`.`lock_version`; restore vs trash via existing `page.restore`/`post.restore`; indefinite retention (closes DOC-02 §33 gaps for Task 4.9).

ADR-020: V1 Page/Post Archive — `PUBLISHED → ARCHIVED` via `page.archive` / `post.archive`; leave archive by republish (`ARCHIVED → PUBLISHED`) via existing `publish()` / `page.publish` / `post.publish`; `PAGE_ARCHIVED` / `POST_ARCHIVED` inbound; `*_PUBLISHED` on republish; no `*.unarchive`, no `*_UNARCHIVED`, no previous-status schema (Task 4.11A).

ADR-006: Transaksi dua fase (lease_until), idempoten, penanganan late catch-up, dan audit otomatis pada scheduled_actions.

ADR-021: V1 scheduled PUBLISH/UNPUBLISH contract — `scheduled_actions` DDL (MariaDB `pending_guard` unique); Site TZ UI / UTC storage; OCC execute-against-live (SKIPPED `LOCK_VERSION_CONFLICT`); skip TRASH/ARCHIVED/PENDING_REVIEW; reuse publish/unpublish permissions; no new AuditEvent for skip/cancel (Task 4.12B).

ADR-015: Binding Post ke template wajib `custom-post` tanpa `template_key` tersimpan; schema payload milik Manifest; baseline field `body` (RICH_TEXT, optional at draft) per Task 3.8C.

3. Assets, URL Namespace & SEO Engine

ADR-003: Routing dwibahasa Strategy B (Primary di root /slug, Secondary di /en/slug), resolusi deterministik fallback canonical, dan hreflang kondisional.

ADR-024: Phase 7 V1 contract — reuse translation tables; Settings primary/secondary locale; url_redirects + SEO columns (7.1B); LocaleFilter; sitemap/robots; global URL namespace; canonical/hreflang rules (Task 7.1A).

ADR-016: V1 public Post path `/news/{slug}` + `/en/news/{slug}`; Theme view `templates/custom-post.php`; global namespace collision + indistinguishable public 404 for non-PUBLISHED.

ADR-017: V1 public Page path `/{slug}` + `/en/{slug}` (flat, non-nested hierarchy); Theme view `templates/{templateKey}.php` (typically `custom-page`); PUBLISHED-only; Post `news` route precedence; indistinguishable public 404 for non-PUBLISHED.

ADR-007: Pemisahan fisik gambar di public/uploads/images/ (master size via ext-gd), dokumen privat di writable/uploads/documents/ via 32-char crypto token stream, dan dependency checking sebelum penghapusan.

ADR-018: V1 Media foundation — `media_assets` schema; `download_token` (supersedes DOC `download_hash` naming); IMAGE/DOCUMENT MIME allowlists (SVG rejected); upload caps 5 MiB / 15 MiB; public image URL `/uploads/images/{storage_key}`; baseline profile `cms_default` when Theme `media_profiles` is empty.

4. Infrastructure, Performance & Project Governance

ADR-009: Caching filesystem FileHandler native CI4 4.7+ dengan targeted cache invalidation (deleteMatching) dan isolasi total pada Theme Preview.

ADR-025: Phase 8 V1 public Page/Post File Cache population — ADR-009 keys in FileHandler-safe dots (`content.page|post.{theme}.{locale}.{slug}`); reverse-index via Phase 4 `page.public.{id}` / `post.public.{id}`; cache package = Public*ViewDto + PublicSeoViewDto; PUBLISHED-only; no negative/redirect caching; TTL safety-net 3600s; locale Settings changes must invalidate presentation caches (Task 8.1A).

ADR-010: Kompilasi CSS statis via standalone Tailwind CLI per tema/admin, bebas Node.js di server produksi; Control Panel Alpine/Quill sebagai aset JS/CSS ter-vendor di public/assets/admin/.

ADR-011: Batasan mutlak ketiadaan persistent queue/worker/Redis/Docker di shared hosting; synchronous workload dibatasi secara terukur.

ADR-012: Kebijakan branch terisolasi (upgrade/* dan security/*), toleransi zero deprecation internal, dan verifikasi non-destruktif via cms:integrity-check.

ADR-013: Struktur layered standar CI4 (Controller → Service → Model), penolakan HMVC app/Modules/, dan penempatan PHP views tema di luar web root publik (app/Views/themes/).

Governance

ADR berstatus Accepted bersifat mengikat terhadap implementasi SMITE CMS V1.

Perubahan terhadap keputusan yang telah Accepted harus:

melalui review terhadap dokumen dan ADR yang terdampak;

menghasilkan ADR revisi atau ADR pengganti bila keputusan arsitektural berubah;

memperbarui hubungan/traceability pada indeks ini.

ADR tidak boleh diubah secara diam-diam hanya untuk menyesuaikan implementation detail. Jika keputusan dasarnya berubah, perubahan tersebut harus terlihat dalam history ADR.
